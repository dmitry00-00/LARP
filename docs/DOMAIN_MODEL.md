## 1. Пять сущностей

```
   Archetype  ──< ArchetypeSlot >──  SlotType  (словарь)
       │                                 │
       │ регламент, окно лет, регион      │ зоны тела, слой
       │                                 │
       └──────── матчинг ────────►  Lot  ─┘        Maker ──< Service
                                    │ offer | want
                                    │ размеры, состояние, провенанс
                                    ▼
                                  Deal (шаг 3, не в MVP)
```

### Archetype — нормативный комплект

Аналог `Position` + `PositionMask` из recruit. Не «стиль персонажа», а
набор проверяемых ограничений.

| поле | тип | смысл |
|---|---|---|
| `id` | slug | `ck14`, `vk10` |
| `title` | текст | «Чешский рыцарь» |
| `region` | справочник | Богемия · Нюрнберг · Италия · Степь… |
| `year_from` / `year_to` | int | **окно лет**, не «век»: век — это подпись, окно — это то, чем считается конфликт |
| `ruleset` | enum | `bi` · `imcf` · `magna_carta` · `club` · `none` |
| `discipline` | enum | `hmb` · `reenact` · `larp` · `hema` |
| `required_slots[]` | связь | обязательные позиции |
| `layers` | json | порядок слоёв 1–4 |
| `sources[]` | json | музейные прототипы, иконография |

⚠ **`ruleset` и `discipline` — разные оси.** В `data.jsx` сегодня они слиты
в одно поле `discipline: "HMB / реконструкция"`. Разделить до первого
импорта: один и тот же комплект допущен у BI и не допущен у IMCF, и
валидатор без этого поля будет уверенно врать.

⚠ **Век — не окно.** «XIV в.» в тексте объявления надо разворачивать в
`1300–1400`, а «к. XIV в.» — в `1370–1400`. Конфликт считается по
пересечению окон, а не по сравнению строк.

### SlotType — словарь позиций

Аналог дерева инструментов и `canonical_skills` (в recruit — ~467
инструментов с алиасами). **Самая недооценённая часть работы.**

| поле | смысл |
|---|---|
| `id` | `helm`, `pauldron`, `couter` |
| `label_ru` / `label_en` | «Наплечники» / spaulders |
| `aliases[]` | «плечи», «наплеч», spaulder, pauldron, «оплечье» |
| `zones[]` | зоны тела из `BODY_ZONES` (23 шт., есть в прототипе) |
| `layer` | 1 поддоспешник · 2 кольчуга · 3 латы · 4 сюрко |
| `parent_id` | под-слоты (комплект руки = наручи + локти + поручи) |
| `measures[]` | какие обмеры обязательны именно для этого слота |

**Без словаря алиасов LLM разложит объявления в разные слоты и матчер
увидит пустоту.** В recruit ровно это стоило 3k потерянных кандидатов —
позиция без заполненной маски не извлекала инструменты.

### Lot — предмет: и предложение, и запрос

**Одна таблица на обе стороны рынка.** Это главное структурное решение
документа. `direction` = `offer` | `want`.

| поле | offer | want |
|---|---|---|
| `direction` | `offer` | `want` |
| `slot_id` | что это | что ищут |
| `archetype_hint` | подо что сделано | подо что ищут |
| `year_from/to` | датировка вещи | приемлемое окно |
| `region` | откуда стиль | приемлемые регионы |
| `condition` | new · used · damaged · project | приемлемое состояние |
| `price` / `currency` | цена | **потолок бюджета** |
| `measures` json | обмеры вещи | обмеры **тела** покупателя |
| `steel_mm` | толщина | минимум по регламенту |
| `weight_g` | масса | потолок |
| `photos[]` | обязательны для used | — |
| `city` / `country` | где лежит | куда везти |
| `seller_ref` | контакт | контакт |
| `source_id`, `raw_text`, `posted_at` | откуда пришло | — |
| `status` | active · sold · stale · dead | active · closed |

Почему одна таблица, а не две: фильтры, фасеты, нормализация, извлечение и
матчинг у них **общие**, различается только направление. Две таблицы дадут
две копии одной логики, которые разъедутся на третьем месяце. В recruit
кандидат и вакансия разъехались именно так и матчинг пришлось строить
поверх, третьей сущностью.

### Maker — кто делает и чинит

`id`, `title`, `country`, `city`, `contacts`, `specialties[]` (слоты и
эпохи), `lead_time_days`, `queue_open` (bool), `verified_at`, `rating`.

Ценность агрегатора здесь — **не цена, а прозрачность очереди**: «кто
возьмёт заказ и когда». Такого не даёт ни один магазин.

### Service — услуга как первоклассная сущность

Нового в recruit нет ничего похожего. `kind`: `repair` · `refit` (подгонка
чужого б/у) · `custom` (ковка) · `consumable` · `appraisal` (оценка и
допуск) · `logistics` · `rent`. Поля: `maker_id`, `slot_scope[]`,
`price_from`, `turnaround_days`, `city`, `remote` (можно ли по почте).

`refit` и `appraisal` — коммерческий шов продукта: они превращают
неудавшийся матч в сделку. «Не подходит по груди на 4 см» → «подойдёт после
подгонки, вот три мастера, срок 10 дней, от $60».

## 2. Матчинг: контракт

Три независимых предиката. Считаются раздельно, показываются раздельно,
**никогда не складываются в одно число до самого последнего шага**.

### 2.1 Слот-матч (структурный)

Для каждого слота архетипа исход из четырёх:

- `matched` — лот закрывает слот;
- `gap` — слот обязателен и пуст;
- `extra` — лот есть, слота в архетипе нет;
- `conflict` — **лот есть, но не годится**: окна лет не пересекаются, либо
  регион не входит в допустимые, либо регламент не тот.

`conflict` — категория, которой в recruit не было, и здесь она главная:
именно она превращает витрину в валидатор. В прототипе уже работает
(наколенники ок. 1340 в архетипе к. XIV в.).

### 2.2 Размерный матч

Три исхода, и третий важнее первых двух:

- `fits` — все обмеры в допуске;
- `no` — за пределами переделки;
- `refit` — **подойдёт после подгонки** → сразу ссылка на услугу `refit`.

Обмеры сводятся к телу, а не к «размеру L»: обхват груди, обхват головы,
длина руки от плеча, длина предплечья, длина голени, обхват бедра, размер
стопы. Всё в см. **Лот без обмеров для матчера не существует** — прямой
перенос правила про кандидата без инструментов.

### 2.3 Состояние и допуск

`steel_mm` против минимума регламента, наличие фото, наличие трещин,
переклёпки. Для `used` без фото — исход `unknown`, и это **не то же самое,
что плохое состояние**: неизвестность отдельно, иначе честные продавцы без
фото проваливаются в брак.

### 2.4 Чего не делать сейчас

**Эмбеддинги — только для поиска, не для ранжирования.** В recruit замер
04–10.07.2026 (46 вакансий, 827 размеченных пар, ndcg@10): структурный
матчинг 0.740 ≈ гибрид 0.737 ≫ лексика 0.712 ≫ BGE-M3 0.590 ≫ MiniLM 0.479.
Эмбеддинги прироста над структурой не дали. Домен здесь ещё более
структурный. Не тратить на них первый горизонт.

**Обучаемый ранкер — после ~800 размеченных пар.** Там же: ридж на
структурных фичах дал +0.094 ndcg над ручным взвешиванием (p=0.001). До
этого веса ставятся руками, и это нормально.

## 3. Извлечение из объявления

Схема, которую LLM обязана заполнить из `raw_text`. Порядок конвейера
скопирован из recruit — он там отработан:

```
watch (TG/VK/форум)   → inbox_items (status='raw', raw_text ВСЕГДА)
classify_post         → offer | want | service | event | other
  ├ dedup             → skipped, skip_reason='duplicate'
  └ topic_gate        → skipped, skip_reason='off_topic'   ⚠ помечает, не удаляет
extract_lot           → Lot(direction=offer|want) + Measures
extract_service       → Service + Maker
```

Оба гейта **помечают**, а не удаляют: отсев обязан быть обратим. Ручное
добавление входит **после** классификации (`status='classified'` сразу):
человек уже решил, гейты ему вредны.

**Обязательные поля извлечения** и что делать при отсутствии:

| поле | нет в тексте |
|---|---|
| слот | → `needs_review`, не угадывать |
| цена | оставить null, лот живой (часто «цена в личку») |
| обмеры | → флаг `no_measures`, лот виден, но **не участвует в размерном матче** |
| фото | для `used` → флаг `no_photo`, понижает доверие |
| датировка | взять из архетипа продавца, пометить `inferred` |

**Отдельный извлекатель — обмеры.** В объявлениях они пишутся десятком
способов: «57–60», «на голову 58», «грудь 110 см», «под рост 180». Это
регулярки плюс LLM, и это отдельный модуль (в recruit ровно так сделан
`skills/salary.py` — один парсер зарплат на всех извлекателях).

| Механизм | Как переносится |
|---|---|
| `inbox_items.raw_text` как архив | **дословно.** Ошибку разбора можно переиграть, ошибку обхода — нет |
| Гейты помечают, а не удаляют | дословно |
| Контроль лимитов Telegram (`telemetry.py`, токен-ковш, самокалибровка) | **дословно и заранее.** Аккаунт — единственный измерительный прибор; узнать про лимит можно только словив FloodWait, то есть потеряв сутки |
| Чтение `t.me/s/` вне квоты | дословно |
| Словарь канонических сущностей с алиасами | механика та же, содержимое новое (слоты вместо инструментов) |
| Структурный матчинг `matched/gap/extra` | плюс новый исход `conflict` |
| Провенанс записи (откуда пришла) | плюс **провенанс вещи** — это другое и это фича, а не техполе |
| Нормализация валют, курс раз в час, статический фолбэк | дословно; валют больше (₽ ₸ $ € грн) |
| Журнал массовых правок (`analysis/mutations/*.jsonl`) | дословно, когда появится БД. Дважды за месяц в recruit массовая правка прошла без следа |
| `verify_sql.command` — страж пар «таблица→колонка» | дословно, когда появятся модели |
| Ops-скрипты `check/` только на чтение, с шапкой | дословно |
| Spine/Tablet, TreePicker, фасетная таблица | дословно на уровне паттерна |
| Боты: отдельный процесс на каждого, роутеры-синглтоны, 64 байта на `callback_data` | при появлении бота — читать ловушки recruit целиком |

**Что НЕ переносить:**

- эмбеддинги в ранжировании (см. §2.4);
- три поколения матчинга одновременно — здесь начинать сразу с одного;
- разделение кандидата и вакансии на две сущности — здесь одна `Lot` с
  `direction`;
- сложную онтологию компетенций и `one_of_*` групп — у слотов нет
  взаимозаменяемости такого рода (кираса не заменяется наплечниками).

## 5. Ловушки модели

| Ловушка | Правда |
|---|---|
| «размер L» | не существует. Только обхваты и длины в см |
| «б/у» как состояние | без фото и толщины стали это не состояние, а отсутствие данных |
| цена как одно число | медиана по слоту без разреза по размеру и состоянию — фальшивое число |
| «XIV в.» как значение | подпись. Значение — окно `1300–1400` |
| дисциплина = регламент | разные оси, оба поля обязательны |
| один слот — один предмет | комплект руки закрывает три слота; нужен `parent_id` и разбор комплектов |
| «конфликт» = «не подходит» | три разных отказа: анахронизм, размер, допуск. Смешивать — терять причину |
| лот живёт неделями | часами. `stale` наступает быстро, и это метрика качества обхода |
