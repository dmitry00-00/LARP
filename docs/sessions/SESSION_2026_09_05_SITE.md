# Страница-агрегатор: от прототипа к продукту — 05.09.2026

> **Триггер:** «HMB-Market (standalone).html удалить, создать полноценную
> страницу сайта, которая и будет функционировать как агрегатор».
>
> **Метод:** сборка с нуля + прогон в Chromium (Playwright) с проверкой
> каждой заявленной функции. Проверено прогоном, а не чтением.
>
> **Стенд:** `file:///…/site/index.html`, 1600×980, deviceScaleFactor 2.

---

## 1. Что удалено и что появилось

`HMB-Market (standalone).html` (2,6 МБ) удалён: он был собран до реестра и
разошёлся с исходниками — держать рядом две расходящиеся версии одного
экрана дороже, чем пересобрать.

Появился каталог `site/` — **продуктовая страница**, отдельная от
дизайн-прототипа в корне:

```
site/index.html        каркас, два тега <script>
site/app.css           17 КБ стилей
site/app.js            46 КБ, ~830 строк, ванильный JS
site/seed.js           встроенный корпус (нужен для file://)
site/data/feed.json    тот же корпус как фид — контракт для парсера
site/tools/gen_seed.py детерминированный генератор (seed=20260905)
site/README.md         что умеет, откуда данные
```

## 2. Три решения, которые стоит помнить

**Ванильный JS вместо React.** Прототип тянет React и Babel с CDN и
транспилирует в браузере — это дев-режим, для продукта негодный. Варианта
было два: поставить сборку или обойтись без фреймворка. Приложение
табличное, состояние плоское, узлов немного — фреймворк не окупается, а
сборка добавляет шаг между «поправил» и «увидел». Итог: ноль зависимостей,
страница открывается двойным кликом.

**Двойной источник данных.** По `http(s)` страница делает
`fetch("data/feed.json")`; из `file://` fetch запрещён CORS, поэтому рядом
лежит `seed.js` с тем же корпусом в `window.HMB_SEED`. Один и тот же JSON в
двух обёртках: `feed.json` — контракт, который будет писать парсер, `seed.js` —
чтобы страница работала без сервера.

**Корпус генерируется скриптом, а не пишется руками.** 348 записей
воспроизводимы из `seed=20260905` и помечены `meta.synthetic = true`;
страница пишет это в статус-строке, а курсы валют помечены как заглушка.
Домашнее правило («число без даты — враньё») требует, чтобы демо-данные
нельзя было случайно процитировать как рыночные.

## 3. Что страница делает

Реестр в одной таблице: предложение ▲ · спрос ▼ · услуги ◆. Фасеты со
счётчиками, потолок цены поверх гистограммы, сортировка по любой колонке,
поиск по названию, городу, мастеру и **алиасам слота**. Размерный матч
против ваших обмеров («подойдёт / подгонка / не тот / нет обмеров», допуск
4 см). Конфликт эпохи против выбранного из восьми архетипов. Карточка лота:
посадка по каждому обмеру, шкала периода, цена против медианы слота,
мастер, услуги под слот, похожие, источник. Подписки на фильтр со счётчиком
новых. Профиль с обмерами и валютой. Состояние фильтров в `#`-хвосте URL.
Клавиатура: `/`, `j`/`k`, `Esc`.

## 5. Дефекты, найденные прогоном, и как исправлены

- **Блок «дефицит рынка» показывал нули и минусы.** Разница `▼−▲` работает
  только когда стороны сопоставимы; на корпусе, где предложений втрое
  больше запросов, она вырождается. Заменено на **напряжённость** —
  запросов на одно предложение; метрика читается при любом размере выборки.
- **Услуги в карточке ранжировались произвольно** — универсальные
  расходники (`scope: *`) вытесняли услугу под конкретный слот. Введён
  порядок: подгонка вперёд, если лот «почти подходит», затем точные по
  слоту, затем универсальные. Проверено на поддоспешнике: три «перешива
  под обмеры» встали выше «ремней и пряжек».
- **Paperdoll сливался с фоном** — зоны архетипа рисовались нейтрально
  серым по тёмному телу. Подкрашены латунью, теперь покрытие читается.
- Плотность: строки 6 px → 4 px по вертикали, в экран влезает 20 строк.

## 6. Что осталось за кадром

- Виртуализация списка: 348 записей рендерятся мгновенно, десятки тысяч —
  нет. Порог примерно на 3–5 тысячах.
- Фото — заглушки-плейсхолдеры: настоящие появятся, когда парсер начнёт их
  качать при обходе.
- «Открыть оригинал» показывает имя источника, а не прямую ссылку: в
  корпусе нет URL постов, они появятся с парсером.
- Мобильная вёрстка: боковые панели скрываются ниже 1240 и 940 px, но
  таблица под телефон не переработана.
