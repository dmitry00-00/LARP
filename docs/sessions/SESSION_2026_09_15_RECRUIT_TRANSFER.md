## 3. Что перенесено буквально и почему это безопасно

Критерий отбора — **ноль импортов из домена recruit**. Проверено grep'ом по
каждому файлу: приёмный набор (`telemetry`, `sidefiles`, `accounts`, `state`,
`tg_web`, `telegram`, `llm`, `dedup`, `salary`, `ner_extractor`) тянет только
`structlog`, `httpx`, `pydantic-settings` и лениво `telethon`. Из бэкенда взяты
три файла, у которых домена нет по построению: крючок на Engine, страж
колонок по метаданным, генератор схемы. `fx.py` был единственным с доменной
привязкой (модель `CurrencyRate`) — развязан миксином, см. `kernel/README.md`.

Не перенесено и почему — там же, раздел «Что в ядро сознательно НЕ взято».

## 4. Дефекты, найденные переносом

1. **`fx.classify_currency("₸") → unknown`.** В `_ALIASES` recruit есть `$`
   и `€`, но нет `₸`, `₽`, `£` и кириллических «тенге», «руб». Для recruit
   это хвост (валюта приходит кодом от парсера), для базы в KZ — ядро.
   В `kernel/db/fx.py` добавлено; **в recruit не правил** — их код, их
   решение. Странность владельцу recruit: строка 4 в §7.
2. **Два теста `test_flood_guard.py` тестируют скилл, а не клиент**
   (`check_dead_channels` — бюджет внутри прогона). Вырезаны из копии, урок
   оставлен комментарием: каждый скилл обхода обязан звать
   `telemetry.meter().allowance()` **в цикле**, не только на входе.
3. `mutation_audit.py` и `mutation_journal.py` ищут корень репозитория по
   `parents[N]` — при переносе глубина изменилась (4 → 2). Такая привязка к
   глубине дерева — ловушка для любого следующего переноса.

## 5. Опыт recruit за 05–15.09 для *наполнения* HMB-Market

В LARP-доках этого нет — recruit набил эти шишки уже после того, как они
были написаны. Порядок — по цене повторения.

1. **Три числа вместо одного, с первого дня.** У recruit было «427k
   кандидатов», работать можно с 5 310 (контакт ∧ инструменты ∧ дата). Для
   лотов: всего / с обмерами ∧ фото / с живым контактом. Первое — строки,
   третье — продукт. Все три — в CLAUDE.md, с датой.
2. **Веб-транспорт заливает очередь.** Когда `watch_web` встал в цикл (10.09),
   сырой хвост вырос на 48k и растёт 5–15k/день; узкое место —
   классификация под LLM-окном. `t.me/s/` дёшев по квоте, но не по разбору:
   пропускную способность LLM считать **до** подключения источников.
3. **У курсора обхода обязан быть писатель.** `last_polled_at` 17 дней никто
   не писал — обход перечитывал одни и те же 74 канала и выглядел живым.
   Первый же `ops/check`: «у каждого поля состояния есть writer».
4. **Зависший сокет останавливает последовательный цикл без алерта.** Живой
   процесс с нулевым CPU. Сторож — по времени шага; лог-файл — не
   свидетельство жизни.
5. **Источники судить по выходу с первой недели.** 2 091 канал импортировали
   оптом, никто не оценивал; решение владельца — понижать нулевые, не
   резать. `yield per source` — колонка реестра источников, не отчёт.
6. **Прайс-лист мастерской — не 20 лотов и не один лот.** `vacancies.is_digest`
   (14.09): посты-агрегаторы завышали спрос джунов на 30–40 %. «В наличии:
   3 бацинета, 5 пар перчаток» — свой тип на приёме, вне подсчётов по слоту.
7. **Пустой слот — почти всегда проводка, а не спрос.** 36 из 52 должностей
   были пусты из-за того, что слаг не подключён к детектору, — ни одна из-за
   отсутствия спроса. На каждый слот — цепочка «слот → алиасы → экстрактор →
   лоты» одной командой (образец `ops/check/position_wiring.command`).
8. **Экстрактор не виноват; деньги — в ложных алиасах.** Потеря требований
   при извлечении — 2.1 % (06.09); настоящий дефект — ключи, зажигающиеся на
   лексике самого объявления (3.1 % строк, 13.09). Для лотов: «ремонт» в
   «ремонт не требуется», «подгонка» в «подгонки не было», «шлем» в «отдам в
   придачу к шлему». Лечится контекстом (`_Guard.forbid` в `ner_extractor`),
   не удалением ключа.
9. **Иноязычный пост не срабатывает ни на одном словаре и проходит всё.**
   167 каналов в recruit не задели ни один фильтр. LARP с первого дня RU+EN
   (+UA/KZ): алиасы по языкам; гейт для незнакомого языка отвечает `unknown`,
   а не `ok`.
10. **`published_at` ≠ `created_at`.** Свежесть — по дате поста, не по дате
    приёма (миграция 0054 в recruit сделана постфактум). Метрика `stale` без
    этого — про скорость парсера, не рынка.
11. **Синтетика помечается в БД, не только в фиде.** 430k кандидатов recruit
    оказались скрапом Habr 2023 года. Колонка `provenance` — в первой
    миграции, чтобы 348 седовых лотов через полгода не стали «рынком».
12. **Колокольчик построчно — свалка** (177 598 строк, 8 прочитано). Сводки
    суточные, ретенция — с первой миграции.
13. **Цикл должен доходить до касания.** У recruit за месяцы — ноль касаний
    и ноль пользователей бота; единственный подписчик дайджеста — без
    инструментов, читать сигнал некому; ранкер LTR заморожен с 11.07, потому
    что учить его не на чем. Для HMB-Market бот — весь Горизонт 2: «подписка
    → алерт → переход к оригиналу» мерить с первого алерта, журнал касаний
    (`outreach_touches`) — с первой подписки.

Плюс две ловушки инфраструктуры, когда появятся сервисы: зона `CronTrigger`
берётся с машины, а не с планировщика (все джобы recruit ходили на три часа
раньше написанного; держать `test_scheduler_schedule.py` с явной зоной);
`/health` возвращает `ok` при мёртвой базе — нужен `/ready`.

## 6. Опыт для интерфейса (правила, не код — `site/` на ванильном JS)

* список выше экрана — **страницы, не скролл**; строки не растягиваются
  (владелец recruit, 14.09);
* карточка по id — отдельная загрузка, не поиск в странице списка (класс
  дефектов «store page is not a lookup table»);
* поверхность = вопрос; **нет оценки без знаменателя** (UI surface contract §10);
* под правило LARP № 7 «важное в один экран» в recruit есть проверка:
  `e2e/lib/layoutChecks.ts` (hard/soft-находки, порог 1.5 экрана на список) +
  `ops/check/layout_audit.command`. Playwright в LARP уже использовался 05.09
  — адаптировать к `site/` можно за час, когда страница получит данные.

## 7. Странности — владельцу

1. **`kernel/config.py` сохраняет имена полей `openclaw_*`** (`openclaw_home`,
   `openclaw_mock_telegram`): их читают перенесённые модули. Переименовать
   в `ingest_*` — отдельная правка с тестами. Оставить или переименовать?
2. **Название пакета `kernel`** — по ROADMAP. Как top-level имя в Python оно
   родовое; при появлении второго проекта-потребителя лучше `hmbkernel` или
   выделение в отдельный репозиторий. Сейчас не трогал.
3. **`state.py` несёт две recruit-таблицы** (`channel_candidates`,
   `github_repos`). Не вырезал: `test_state` ходит по схеме целиком, а
   первая миграция стейта — момент решить, что в нём вообще нужно.
4. **Находка для recruit, не для LARP:** `app/services/fx.py:_ALIASES` не знает
   `₸`, `₽`, `£`, «тенге», «руб». В ленте recruit валюта обычно приходит
   кодом от `salary.py`, так что цена дефекта там мала — но
   `salary_currency_gaps` его должен показывать как `unknown`. Сказать
   владельцу recruit?
5. Порог дедупа 8 бит и `RETENTION_DAYS=30` в `dedup.py` — калибровка на
   вакансиях. Для лотов, где репост одного предмета по пяти чатам — норма,
   а жизнь поста — часы, оба числа надо перемерить на первом реальном корпусе.
